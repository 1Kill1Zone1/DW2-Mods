# Freight Dispatch 0.2.2 — checked local candidate

**0.2.2 is prepared, not installed. The current GOG profile still uses 0.2.1.** This update addresses the owner's first live FD UI feedback.

Drag the free title area at the left of the header with the left mouse button. Both tabs move together; release commits the position to local machine preferences at `%LOCALAPPDATA%/DW2FreightDispatch/window-v1.json`. The next open/restart restores it, and resolution changes clamp the window back on screen. Default placement sits beside the actual native selected-object column when space permits. Tabs, close, search, numeric fields and row clicks do not start a drag. Focus/occlusion loss cancels unfinished gestures. Invalid preference files fall back without being overwritten; I/O failure keeps a usable session position and logs the persistence failure.

The update adapts the exact loaded older Battle Log/Weapon FX Tuner/Waypoints dock helpers so they recognize the currently owned, registered FD panel. Its four tool buttons remain available and change the selected tool. A same-name foreign control, unrelated windows, Research and modal dialogs are not exempted. Peer DLLs are not rewritten; the three narrow runtime postfixes are declared with their target assemblies and optional load-after dependencies.

Dispatch resources come from the selected **owned base or spaceport**, not from the destination. A selected colony is not a source in this version. The destination defaults to the capital independently. Missing source/empty own free cargo now have explicit explanations; empty resource fields are hidden, and Start is disabled when there are no resource choices.

The full harness loads actual installed peer assemblies and tests their real dock controls/helper logic with the real owned FD window; peer-body switching uses controlled panel fixtures, not rendered peer content. The older84-check probe intentionally uses an unowned same-name panel and therefore still requires the old helpers to block it. No live rendering, autonomous travel or FPS claim.

**0.2.1 fixes both independently reproduced defects and includes the Freighters overview introduced in 0.2.0.** Open **FD → Freighters** without selecting a base. The **Dispatch** tab retains existing controls.

The read-only Freighters tab lists every own civil freight hull, including empty, damaged, refitting and unfinished ships. Select a row for actual hold quantities (and a separate smuggling hold when present), the current mission and its remaining native commands, ordered queued missions, and a separately labelled suspended/revert mission. Queued missions start from their first command because GOG 1.3.8.4 rebuilds them on assignment. Fuel tanks and mission cargo plans are never added to actual cargo.

Use name search, resource arrows (actual/assigned cargo), State and Assignment filters, Ships pages and Details pages. Long names and mixed cargo are available in full through detail pages. Current transport missions show pickup/delivery endpoints and each contract's resource and contracted/picked/delivered counters. FD reasons require matching own ship/order/contract/resource/source/destination identities; stale metadata is explicitly unconfirmed. Ordinary AI selection reasons are labelled unrecorded rather than invented. No decision history or prediction of unassigned voyages is added.

Samples refresh at most once every two seconds while the tab is open and unobstructed, with sample time/age shown. Concurrently changing or invalid ships are marked unavailable after one retry; failed whole samples retain an explicitly stale prior snapshot. Native data remains readable if FD session metadata faults, with a warning. A missing required Matrix at initial mod startup still follows the existing fail-closed dependency behavior.

**Fixed in 0.2.1:** successful Priority changes clear their confirmation so live task waiting status remains visible. Loaded voyages keep updating Delivered during a persistence fault; duplicate callbacks do not double-count. Before saving, valid retained state is cleaned and committed again with readback verification. The fault latch still prevents pickups until reload. Failed Start/Priority commits roll back their local command so save recovery cannot resurrect a rejected action.

The native DWGame.SaveGame entry is guarded **before it opens/truncates its target**. If cleanup or the verified commit fails, the native save body is skipped, the existing file remains intact, and a failure notice is queued until the game returns to Running. A thread-local scope avoids a second fallible Matrix commit after file opening and resets on success, skip and exception. Raw corrupt payloads without valid loaded state are still preserved. The actual native file-opening order was inspected; isolated tests exercised the hooked SaveGame failure path and verified an existing test file byte-for-byte, plus real serialization/reload of a completed faulted delivery. These are not a live full-game save or pixel-rendering claim. Installation is recorded separately in the verified receipt; no game launch is part of this update.

Standalone local module for GOG Distant Worlds 2 1.3.8.4. The accepted scope is in `docs/Freight Dispatch.md`. Requires Positronic Matrix; cooperates with the actual installed Freighter Logistics. No installation, profile modification or live campaign edit is part of building/checking this module.

Select an owned base and open Freight Dispatch. Normal/High changes source preference for existing native demand. A dispatch task selects an owned colony/spaceport, resource-specific manual retain amounts and a concurrent own-freighter limit. The capital is the default destination. A base and its colony sharing the same physical hold cannot be opposite endpoints.

The panel distinguishes actual allocated hulls from requested quota. The denominator is the current completed own small/medium/large civil freighter fleet, including damaged and refitting ships; it is not an availability estimate. Cancelling loaded voyages remain allocated until their native transport mission releases them. Ship IDs are deduplicated.

Contracts, reservations, loading and unloading use native game APIs. Free Cargo already excludes CargoReserved; existing reservations are not subtracted twice or commandeered. A per-call stock-list argument replaces automatic retention for task contracts; player settings are not rewritten. New reverse orders are suppressed, and only uncontracted reverse demand is retired. Existing inbound contracts are preserved. Source loss/capture prevents new pickups and cannot suppress the new owner's economy.

Task orders expose no uncontracted demand to the ordinary scheduler. At most one native contract is created per allocation, and quota checks use actual mission identities. The native candidate search skips loaded/foreign/ineligible ships instead of rejecting only its first choice. Fuel orders run before dispatch. Task top-ups are disabled so Freighter Logistics cannot silently enlarge task loads.

Cancellation stops unstarted pickups and releases native reservations. A partially loaded voyage releases its unloaded balance and continues with cargo already aboard. Delivered quantities come from native contract counters, not estimates or direct cargo edits.

State is per campaign/player, stored through Matrix with checked two-bank chunk commits. Invalid state fails closed; there is no session-only fallback. Native order, contract, resource and endpoint identities are reconciled before reuse.

If a Matrix commit fails after assignment, unloaded task allocations are cancelled natively and loaded deliveries remain allocated. Known faulted task voyages cannot pick up more cargo or receive Freighter Logistics top-ups. The save barrier repeats cleanup before serialization; if that cleanup itself fails, it stops the save rather than serialize an unrecorded allocation. Missing/corrupt payloads are preserved.

Current route guard checks both native paths and the existing tank's range for pickup plus delivery. It does not assume future refuelling at pickup. An insufficient current tank produces an explicit waiting reason; this conservative restriction must be included in candidate verification and manual review.

Checks live under `check/`. Only the lead runs them through the repository's single-check runner. They load an isolated campaign copy, invoke actual native load/unload APIs at fixture docks, and write uniquely named roundtrip artifacts beside the check executable. Such checks do not establish live travel, UI rendering, or FPS. The real source save and installed game/mod files must remain hash-identical.

Fixture cargo holds preserve the native indexing/rollup flags (both true for the loaded Ghost Fleet Base). A parameterless CargoList does not reproduce that hold behavior: it can leave duplicate resource rows that native GetAmount and cancellation do not aggregate. Reservation tests therefore use correctly initialized native holds and independently sum rows for conservation checks.
